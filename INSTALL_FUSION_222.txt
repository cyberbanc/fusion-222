FUSION-222 v1.0.2 — INSTALL (v1.3.6.6 RETRO ONLY)
======================================================

1. Create/update the Railway service `fusion-222` from this GitHub package.

2. Keep it in the SAME Railway project as the existing `fusion-ev` service.

3. IMPORTANT: do NOT create another PostgreSQL database.
   FUSION-222 must point DATABASE_URL to the SAME existing Postgres used by fusion-ev:

   DATABASE_URL=${{Postgres.DATABASE_URL}}

4. Replace the Railway variables with the complete block from
   RAILWAY_VARIABLES_FUSION_222.txt.

   The corrected package uses dedicated private tables:
   - fusion222_v1366_decisions
   - fusion222_v1366_state
   - fusion222_v1366_snapshots

   This intentionally avoids any old FUSION-222 draft state that may have been initialized from ALL_VERSIONS.

5. Deploy.

6. Open /healthz. Expected: ok=true, service=FUSION-222.

7. Open /health and check tables:
   - base_decisions_read_only = <auto-detected main Fusion history table>
   - decisions = fusion222_v1366_decisions
   - state = fusion222_v1366_state
   - snapshots = fusion222_v1366_snapshots

8. Open /status?history=none. On the supplied 2026-08-11 v1.3.6.6 snapshot, before new live FUSION-222 trades, expected retro values are approximately:
   - bank $1,090.39
   - PnL +$590.39
   - trades 149
   - W/L 84/65
   - WR 56.38%
   - PF 1.413
   - Max DD $109.71
   - scope_version = 1.3.6.6
   - all_versions_replayed = false

   If the main v1.3.6.6 database has newer settled decisions before first boot, values can differ slightly.

9. Generate/assign Railway public domain `fusion-222.up.railway.app`.
   If Railway gives another domain, change only API_BASE in TILDA_FUSION_222.html/.txt.

10. Paste TILDA_FUSION_222.html into a Tilda T123 HTML block.

Safety:
- PAPER only.
- The auto-detected main Fusion decisions table is never rewritten.
- Dashboard retro metrics use ONLY the 1.3.6.6 slice.
- Timer also starts from the first 1.3.6.6 decision.
- New FUSION-222 trades continue from the reconstructed v1.3.6.6 virtual bank.
